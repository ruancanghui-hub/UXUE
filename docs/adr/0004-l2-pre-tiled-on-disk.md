# L2 原图纹理在导入时预先切块存盘

M0 实测发现，把一张 2048×2048 的原图作为单张纹理上传，那一帧的耗时在 4.5–11.5ms 之间波动，超出 120Hz 的 8.33ms 预算；在渲染进程里用 `createImageBitmap` 裁切又会阻塞主线程，造成超过 20ms 的帧间隔。因此我们让图片工作进程在导入或生成时用 sharp 把原图切成 1024 的块（相邻块各多带 1px 防接缝），存在 `.cache/` 里；渲染进程分块加载、每帧最多上传一块，全部到齐后再切换显示。L2 块不生成 mipmap，因为 L2 只在接近原图尺寸时显示。代价是每张图多占一份缓存磁盘空间，但 `.cache/` 随时可以删除重建。

# 规格：从参考图提炼视觉主题

> 给实现者 / 其它模型（如 Codex）的完整规格。  
> 术语以仓库根目录 [`CONTEXT.md`](../../CONTEXT.md) 为准。  
> 决策来自 2026-11-13 grill 会话（用户对 Q1–Q12 全部采纳推荐项）。

## 0. 一句话

用户选中**一张**图像卡（通常是品牌 IP / 风格参考），在助手里提出提炼视觉主题的要求（可附带产品主题短句）；助手**只往画布放一张主题卡**，把品牌线索拆成：产品主题、视觉关键词、视觉线索、色板、统一规则；主题卡可选记下**主题来源**（哪张图、哪个版本）。助手**不发起生图**。

## 1. 已锁定的产品决策

| # | 决策 | 选择 |
|---|---|---|
| Q1 | 输入 | **一张参考图 + 可选的产品主题短句**；短句可空，模型可从图猜品类，用户写了则优先 |
| Q2 | 字段形态 | **映射进现有主题卡**；不新开「主色/邻近辅助色…」独立 schema |
| Q3 | 入口 | **助手**（与现有助手流程一致） |
| Q4 | 生效 | **仅当项目还没有生效主题卡时**，新卡自动设为生效；已有生效卡则只新建候选 |
| Q5 | 多选图 | **只允许一张**；多张图像卡选中时拒绝并提示 |
| Q6 | 色值 | 模型**估算** `#RRGGBB`；不准则用户在主题卡里手改 |
| Q7 | 与文字主题 | **合并为一个能力**：有合规选中图 → 看图提炼；无图 → 纯文字生成主题卡（保留原能力） |
| Q8/Q10 | 来源 | 主题卡记下 `sourceImageCardId` + `sourceVersionId`；**不**画来源连线；**不**挪图到主题区 |
| Q9 | topic | 可空；有用户短句优先 |
| Q11 | 无视觉助手 | **明确报错**（需 OpenAI 助手 Key）；本地模拟可伪造一份主题卡便于自检 |
| Q12 | 本规格用途 | 实现依据；本文件即给 Codex / 其它代理的完整说明 |

**本版明确不做**

- 多图合成一张主题卡 / 每图一张主题卡  
- 本地从像素采样主色  
- 画布上来源连线、把 IP 图挪到视觉主题区  
- 来源图换版后主题卡「已过期」（只先记来源，过期逻辑以后再挂）  
- 硅基流动等其它助手视觉供应商（仍属 PLAN §8 G）  
- 助手自动发起生成  

## 2. 领域术语（须与 CONTEXT 一致）

实现与文案必须用下列词，避免括号内 Avoid：

| 术语 | 含义 |
|---|---|
| **参考图** | 导入的、作风格或内容参照的图像卡（品牌 IP 形象图属于参考图，不要另造「品牌图」实体） |
| **视觉主题** | 项目内素材共同遵守的视觉规则（关键词、色、线索、统一规则） |
| **主题卡** | 画布上承载一套视觉主题的卡片 |
| **生效主题卡** | 同一时刻唯一被采用的主题卡 |
| **统一规则** | 造型 / 材质 / 光影 / 色彩协调 四条；统一 ≠ 长得一样 |
| **主题来源** | 主题卡可选挂的来源图像卡 id + 生成时该卡的当前版本 id |
| **从参考图提炼主题** | 助手根据一张选中图像卡（+ 可选产品主题短句）产出主题卡的能力 |
| **助手** | 只放主题卡 / 提示词卡，不生图 |

内容示例（寿司用例，仅作字段示范，非硬编码唯一答案）：

- 产品主题：日式寿司点餐  
- 视觉关键词：新鲜、热闹、亲切、有食欲  
- 视觉线索：寿司、餐盘、轨道、IP 形象、红色  
- 色板角色：主色；邻近辅助色（橘黄、活力与食欲）；深色（标题、正文、轮廓）；暖白（平衡红蓝冲撞）  
- 配色策略 → 写入 **色彩协调** 规则：保留核心色，扩展邻近色；深色做对比，暖白稳定画面  
- 统一规则：色彩协调 / 造型一致 / 材质一致 / 光影一致（见下节字段规范）

## 3. 用户流程

1. 用户导入品牌 IP（或任意参考图）到画布，成为一张**图像卡**。  
2. **只选中这一张**图像卡。  
3. 打开助手（⌘J），发送提炼主题的意图，例如：  
   - 「从这张图提炼视觉主题」  
   - 「从这张 IP 建立视觉方向，产品主题是日式寿司点餐」  
4. 助手返回短回复 + 一张主题卡草稿；系统把主题卡放到**视觉主题区**。  
5. 若当时没有生效主题卡 → 新卡自动生效；否则仅候选，用户可点「设为生效主题卡」。  
6. 用户可在属性面板改 topic / 关键词 / 色板 hex / 规则。  
7. 之后核心素材生成时，生效主题规则仍按现有逻辑附加到提示词（`themeSuffix`）。

纯文字路径（无选中图像卡，或选中的不是「恰好一张图像卡」且用户明确只要文字主题）：行为与现有「为「某主题」生成主题卡」相同，**不写主题来源**。

## 4. 输入校验（渲染进程，提交助手前）

在「需要看图提炼」的路径上（用户意图是提炼主题且上下文含图，或选中了图像卡且消息像在要主题）：

| 条件 | 行为 |
|---|---|
| 选中的**图像卡**数量 = 0，且消息要求看图 | 提示：先选中一张参考图（品牌 IP） |
| 选中的图像卡数量 ≥ 2 | **拒绝提交**；提示：从参考图提炼主题一次只支持一张图 |
| 选中了非图像卡（提示词卡、主题卡等）且没有恰好一张图像卡 | 不走看图提炼；可走纯文字或提示用户选图 |
| 图像卡当前版本在 `missingVersionIds` 中 | 拒绝；提示原图文件不见了 |
| 助手供应商为 `openai` 且无 API Key | 主进程 / 助手层报错：还没有设置 OpenAI API Key… |
| 助手供应商为 `mock` | 允许；返回本地模拟主题卡（可带上来源 id），不联网 |

发给助手的上下文图：**仅这一张**（不要把选中的其它类型卡片当图塞进 `images`）。  
`AssistantRequest.images` 长度为 1；`index` 为 1。

产品主题短句：从用户 `message` 里取；没有则 `topic` 由模型填写。

## 5. 数据模型

### 5.1 主题卡（`ThemeCard`）扩展

现有字段保持不变，新增可选主题来源：

```ts
interface ThemeCard {
  kind: 'theme';
  id: string;
  name: string;
  x: number; y: number; width: number; height: number;
  topic: string;
  keywords: string[];
  cues: string[];
  palette: ThemeColor[];   // { role, name, hex, note }
  rules: ThemeRules;       // { shape, material, lighting, color }
  groupId: string | null;
  /** 主题来源：从哪张图像卡提炼；纯文字生成时为 null */
  sourceImageCardId: string | null;
  /** 提炼时该图像卡的当前版本 id；无来源时为 null */
  sourceVersionId: string | null;
}
```

- `project.json`：随现有 schema **2** 写入；解析时缺省字段视为 `null`（兼容旧主题卡）。  
- **不必**为此单独 bump schema 主版本，除非仓库另有「加字段必须 bump」的硬性约定；若 bump，须在 `parseProject` 兼容旧版。  
- 删除来源图像卡时：主题卡**保留**，`sourceImageCardId` / `sourceVersionId` 可保留脏引用，或解析时清成 `null` 并 warning——**推荐解析时：图像卡不存在则两字段置 null 并 warning**（与 prompt 清理无效引用一致）。  
- 来源版本 id 在图像卡上已不存在时：保留 `sourceImageCardId`，`sourceVersionId` 置 null（或整段清掉——**推荐只清 version**，属性显示「来源图还在，版本已不在」）。

### 5.2 `ThemeDraft`（助手结构化输出）

助手 JSON **不必**输出 source 字段（来源由客户端在落盘时写入）。  
`ThemeDraft` 仍为：`name, topic, keywords, cues, palette, rules`。

落盘时：

```ts
themeFromDraft(...) + {
  sourceImageCardId: 看图路径 ? imageCard.id : null,
  sourceVersionId: 看图路径 ? currentVersion(imageCard).id : null,
  groupId: null,
}
```

### 5.3 色板角色规范（写入助手指令 + 校验建议）

`palette` 建议 4–5 项，**role 优先使用**（可中文）：

1. `主色`  
2. `邻近辅助色`  
3. `深色`（说明用于标题、正文、轮廓）  
4. `暖白` 或 `浅底`（平衡与留白）  
5. 可选第五色（点缀 / 轨道色等）

每项：

- `hex`：`#RRGGBB`（大写或小写均可，入库前 `normalizeHex`）  
- `name`：给人看的颜色名（如「食欲橘」）  
- `note`：用在哪里、为什么  

非法 hex 的项在 `sanitizeAssistantOutput` / `parseThemeCard` 时跳过（与现逻辑一致）。

### 5.4 统一规则四字段（`ThemeRules`）

| 字段 | 中文标签 | 应写内容 |
|---|---|---|
| `shape` | 造型 | 圆润度 / 比例 / 视角 |
| `material` | 材质 | 质感 / 细节密度 |
| `lighting` | 光影 | 光源 / 阴影 / 高光 |
| `color` | 色彩协调 | 明度、饱和度、冷暖；**配色策略**写在这里（保留核心色、扩展邻近色、深色对比、暖白稳定等） |

原则句可进 `color` 或助手 reply，规则正文保持可执行、短句。

### 5.5 关键词与线索

- `keywords`：4–6 个**感觉/气质**词（新鲜、热闹、亲切、有食欲）  
- `cues`：4–6 个**可看见的物件/形象/标志色**（寿司、餐盘、轨道、IP 形象、红色）  
- 不要把整段文案塞进单个 keyword  

## 6. 助手行为规范

### 6.1 系统指令（须增补现有 `INSTRUCTIONS`）

在「一、生成主题卡」下明确分支：

**有且仅有 1 张上下文图，且用户要求建立 / 提炼视觉主题（或等价意图）时：**

1. 仔细看图：主体、配色、造型、材质、光影、可复用的视觉符号。  
2. `topic`：若用户消息里给出了产品主题，**原样或轻微规范**采用；否则根据画面推断一个短产品主题。  
3. 填满 `keywords`、`cues`、`palette`、`rules`（见 §5）。  
4. `palette` 按主色 → 邻近辅助色 → 深色 → 暖白（+ 可选）组织；hex 为估计值。  
5. **不要**在 theme 流程里输出 `prompts`（`prompts: []`），除非用户同一句还要求写提示词。  
6. `reply` 一两句中文：说明已从参考图提炼主题卡，并提示可改色板。

**无图、纯文字产品主题时：** 保持现有文字生成主题卡行为；客户端不写主题来源。

**反推参考图 → 提示词卡**（现有能力二）保持不变；与「提炼主题卡」不同：前者产出 prompts，后者产出 theme。

### 6.2 意图识别（客户端或模型）

不强制单独 API。推荐：

- 助手快捷芯片 / 预设文案：「从选中的参考图提炼主题卡」  
- 用户自由输入含「主题 / 视觉方向 / 品牌线索 / 提炼」等且选中 1 张图 → 同一路径  

合并入口（Q7）：UI 上可只保留一个「生成 / 提炼主题卡」动作：

- `selectedImageCards.length === 1` → 带图请求  
- `=== 0` → 纯文字（若 message 无主题可提示用户写产品主题）  
- `>= 2` → toast 错误，不请求  

### 6.3 本地模拟（`mock`）

- 若 `images.length === 1`：返回固定或基于文件名的 `ThemeDraft`（可用现有寿司示例结构），`reply` 标明本地模拟。  
- 客户端照常写入 `sourceImageCardId` / `sourceVersionId`。  
- 用于 `check:m3` 类自检扩展（可选）：选中一张图 → 助手 → 主题卡带来源字段。

### 6.4 费用与模型

- 走现有助手供应商与计价（OpenAI Responses + 看图）。  
- 上下文图继续缩到长边 1024（现有 `CONTEXT_IMAGE_EDGE`）。  
- 不在本功能引入新计费 UI。

## 7. UI / UX 规范

### 7.1 助手

- 预设按钮文案推荐：**「从选中的参考图提炼主题卡」**  
- 多选图时点击：toast「一次只支持一张参考图」。  
- 成功：reply 显示在对话里；主题卡出现在视觉主题区（现有 `themeFromDraft` / `applyAssistantDrafts` 布局）。  

### 7.2 主题卡属性面板

在现有主题卡面板增加：

- 若有主题来源：展示缩略图或名称 +「选中来源参考图」按钮（`onSelectCard(sourceImageCardId)`）。  
- 来源缺失：hint「来源参考图已不在项目中」。  
- 不展示「已过期」（本版不做）。  

### 7.3 图层面板

主题卡行无需强制显示来源；可选小标记「有来源」——**非必须，可省略**。

## 9. 验收标准

- [ ] 只选中一张参考图，点「从选中的参考图提炼主题卡」（或等价输入），视觉主题区出现主题卡，字段齐全（topic / keywords / cues / palette≥4 / rules 四条非空或可空但结构完整）。  
- [ ] 色板含主色、邻近辅助色、深色、暖白（或等价 role），hex 为合法 `#RRGGBB`。  
- [ ] 主题卡 `sourceImageCardId` / `sourceVersionId` 指向选中图及其当时当前版本。  
- [ ] 选中两张图像卡时不会调用助手成功返回，并有明确中文提示。  
- [ ] 已有生效主题卡时，新卡不抢生效；无生效卡时新卡自动生效。  
- [ ] 无 OpenAI Key 且非 mock：错误信息明确。  
- [ ] mock 下可完成上述来源字段写入。  
- [ ] 纯文字生成主题卡仍可用，且来源字段为 null。  
- [ ] 用户改主题卡色板 / 规则后，后续生成附加的是改后的生效主题（现有行为回归）。  
- [ ] `npm test` / `typecheck` 通过。  

## 10. 场景表（边界）

| 场景 | 期望 |
|---|---|
| 选中生成结果图（非导入 IP）仍只要「提炼主题」 | 允许：参考图不强制 `origin === 'import'` |
| 用户消息只要反推提示词、不要主题 | `theme: null`，走 prompts（现有） |
| 用户一句里既要主题又要为该图写提示词 | 允许同时非空 theme + prompts；来源只写在主题卡上 |
| 来源图后来被删 | 主题卡仍在；来源 UI 显示缺失；规则仍可用于生成 |
| 来源图换了当前版本 | 主题卡来源 version 仍是旧 id；**本版不标过期** |

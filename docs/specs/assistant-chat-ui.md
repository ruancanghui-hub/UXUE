# 规格：助手会话区 UI（Cursor / Codex 风）

> 术语以 [`CONTEXT.md`](../../CONTEXT.md) 为准：**助手**。  
> 决策来自 2026-11-14 grill 会话（Q1–Q8 全部采纳推荐项）。  
> 本轮只改右侧助手面板的布局与观感，**不改变助手能力**（仍只往画布放主题卡 / 提示词卡，不自动发起生成）。

## 0. 一句话

助手页比属性更宽、可拖拽记住宽度；中间消息列表吃满高度，支持基础 Markdown；底栏大输入 + 建议动作芯片，用起来接近 Cursor / Codex 的聊天区。

## 2. 领域（可选微调 CONTEXT）

**助手**（保持原意，补充 UI 说法即可，不必新实体）：  
右侧可加宽的会话面板；消息列表与输入区是助手的界面，不是新的领域对象。

## 3. 实现要点

### 3.1 宽度

- `.inspector` 仍 272px；`.assistant-side` 默认 420px，可拖左边竖条改宽，夹在 320–560。
- 宽度存 `localStorage`（或现有渲染进程偏好键），键名如 `anye.assistantWidth`。
- 切换属性 / 助手时右侧宽度切换；可用短 CSS transition（可选，不强制）。

### 3.2 布局结构

```
[属性 | 助手]  tabs
上下文条（精简 chip：图 / 主题 / 供应商）
────────────
消息列表（flex:1）
  空态：说明 + 建议芯片
  或：消息流 + 忙碌行 + 「跳到最新」
────────────
建议芯片（有消息时）
输入区（多行 textarea + 发送提示 ⌘↩ / Enter）
```

- Enter 发送、Shift+Enter 换行（保持现有，并兼容输入法 `isComposing`）。
- 用户消息轻底右对齐；助手消息左对齐、弱背景或近乎无气泡，接近文档流。

### 3.3 Markdown

- 仅渲染助手消息（用户消息仍纯文本或同样简单处理）。
- 允许：段落、`**bold**`、`-` / `1.` 列表、`` `code` ``、\`\`\` 代码块。
- 消毒：不执行 HTML；外链可显示为文本或 `https://…` 纯文本，不 `target=_blank` 乱跳（桌面应用内谨慎）。
- 代码块：`overflow-x: auto`；列表区域 `min-height:0; overflow-y:auto`。

### 3.4 列表行为

- 默认贴底；用户向上滚动超过阈值后停止自动滚；出现「↓ 最新」按钮。
- 新消息 / 忙碌状态变化时，仅在「已贴底」时自动滚。

### 3.5 建议动作

- 迁移现有按钮能力为芯片：生成/提炼主题卡、反推、写提示词、列素材清单、拆解、为区块写提示词（显隐逻辑与现在相同）。
- 空会话：列表中央；有消息：输入框上方横滑或换行。

## 4. 验收

- [x] 助手默认约 420 宽，属性 272；拖拽改助手宽并在重启后恢复。
- [x] 消息列表吃满剩余高度，输入贴底；缩窄/加宽时正文与代码块不撑破。
- [x] 空态有说明 + 建议芯片；有消息后芯片在输入上方；快捷能力与改版前一致。
- [x] 助手回复中的加粗/列表/代码块正确显示。
- [x] 上翻后不强制抢滚；有「跳到最新」。
- [x] `npm test` / `typecheck` 通过。

## 5. 非目标

- 多会话历史、真流式 SSE、助手改挂底部、改提示词/工具调用语义、属性栏一并加宽。
